# 移动双臂任务空间算法（开发候选）

本入口将两个末端目标放进同一次有界逆运动学优化，联合求解腰部 pitch、左 RM75 七轴和右 RM75 七轴，共十五个变量。底盘保持固定。原有 RRT-Connect 关节空间规划继续保留。

## 本次新增

- 双末端联合逆解：位置与 SO(3) 旋转误差分别归一化；十五个关节同时受模型限位约束。不是先解两只手、再拼接可能不一致的腰部角度。
- 共同任务框架：给定世界坐标中的物体位姿，以及两个固定的“物体到 TCP”变换，产生两个一致的末端目标。示例使用虚拟抓持框架，不含真实物体。
- 协同路径：按平移和旋转步长细分任务路径，以上一解作为下一点初值；再独立细分关节插值边，逐点检查整机碰撞、两个 TCP 的绝对误差和相对误差。
- 失败明确返回：不可达、碰撞、初始抓持不匹配、误差超限或采样预算不足均抛出 `PlanningFailure`，不把部分路径标成成功。整机适配器在成功与失败后都恢复调用前关节状态。

## 开发环境运行

依赖沿用 `requirements-community.txt`，不新增依赖。无需 ROS 或机器人连接。

```bash
python -m community.dual_task_motion --headless \
  --output community-results/dual-task.json \
  --plan-output community-results/dual-task-plan.json
python -m unittest community.test_dual_task community.test_dual_task_rm75 -v
```

去掉 `--headless` 可在已有 WRS 窗口中播放已检查的关节样本。输出同时给出两手绝对误差、相对误差和已检查样本数；动画仍采用既有演示播放速度，不是时间参数化的控制轨迹。

接口位于 `community.dual_task`：

```python
from community.dual_task import plan_robot_object_motion

# world_object_poses: N 个世界到物体的 4×4 齐次变换。
# object_to_tcp: 两个固定的物体到左右 TCP 的 4×4 变换。
plan = plan_robot_object_motion(
    robot, start_15_rad, world_object_poses, object_to_tcp,
    obstacles=obstacle_models,
)
```

起始关节状态必须已经匹配第一个物体位姿和两手抓持变换。这一入口负责抓持后的共同移动；接近、闭爪与释放另行规划。若要检查物体碰撞，调用前必须把相应碰撞模型注册到机器人上。此实现不建立双手接触力或负载分配模型。

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| 逆解位置/旋转容差 | 0.1 mm / 0.001 rad | 每个目标点两手均需满足 |
| 路径位置/旋转容差 | 1 mm / 0.01 rad | 关节插值采样点对共同目标的误差 |
| 相对位置/旋转容差 | 2 mm / 0.02 rad | 两 TCP 相对变换对固定抓持关系的误差 |
| 任务细分步长 | 5 mm / 0.025 rad | 每次联合逆解的平移/旋转间隔 |
| 关节检查步长 | 0.01 rad | 任一关节的最大采样间隔 |
| 计算预算 | 每次逆解 200 次残差评估；路径 10000 点 | 超出预算拒绝本次路径 |

数值容差不是实机标定精度。模型安装尺寸、腰部和夹爪仍沿用未标定参考值。

## 验证与边界

轻量测试覆盖解析共享腰关节、固定抓持关系、清晰端点之间的薄障碍、不可达目标、180° 姿态误差、输入合法性、采样预算、状态恢复，以及独立读取已固定的厂家 URDF 所得到的十五自由度逆解与路径。

完整 CI 另使用 `MobileDualPitch` 的厂家网格包络、夹爪 TCP 偏移和整机自碰撞检查，执行往返共同位移与环境障碍拒绝测试。

这是局部几何算法候选：碰撞和任务约束通过离散采样验证，不保证连续无碰撞；阻挡路径会失败，尚未在抓持约束流形上搜索绕障路径。没有时间参数化、力矩约束、接触动力学、底盘平衡或真机执行。本接口尚未封装进客户 SDK 或 preview.7 安装包。
